# Инструкция по настройке векторного поиска FAISS

## Решение проблем с NumPy

Ошибка `ImportError: numpy.core.multiarray failed to import` возникает из-за несовместимости версий NumPy 2.x и FAISS, который скомпилирован под NumPy 1.x.

### Решение для Windows:

```powershell
# В виртуальном окружении выполните:
pip install "numpy<2.0" --force-reinstall

# Или конкретную версию:
pip install numpy==1.26.4 --force-reinstall
```

### Решение для Linux/Mac:

```bash
pip install "numpy<2.0" --force-reinstall
```

## Настройка векторного поиска

### 1. Установка зависимостей

Убедитесь, что в `requirements.txt` есть следующие пакеты:

```txt
faiss-cpu==1.8.0
sentence-transformers==2.7.0
numpy==1.26.4
```

Установите их:

```bash
pip install -r requirements.txt
```

### 2. Применение миграций

После изменения модели `ServiceEmbedding` (OneToOne → ForeignKey) примените миграции:

```bash
python manage.py makemigrations search
python manage.py migrate
```

### 3. Построение векторного индекса

Первый раз индекс нужно построить вручную:

```bash
python manage.py build_vector_index
```

**Что происходит:**
1. Загружается модель `paraphrase-multilingual-MiniLM-L12-v2` (~470MB)
2. Для всех активных услуг проверенных компаний генерируются векторные представления
3. Векторы сохраняются в базе данных и индексируются через FAISS
4. Индекс кэшируется в памяти для быстрого поиска

**Требования к памяти:**
- Минимум 1-2GB свободной оперативной памяти
- ~500MB дискового пространства для модели

### 4. Настройка автоматического обновления (3 утра)

#### Linux/Mac (cron):

```bash
crontab -e
```

Добавьте строку:
```bash
0 3 * * * /путь/к/проекту/search/build_index_cron.sh
```

#### Windows (Task Scheduler):

1. Откройте **Планировщик заданий** (Task Scheduler)
2. Создайте **Базовую задачу** (Create Basic Task)
3. Назовите: "Обновление векторного индекса"
4. Триггер: **Ежедневно** (Daily)
5. Время: **3:00**
6. Действие: **Запустить программу** (Start a program)
7. Программа: `python.exe` (полный путь к Python в вашем venv)
8. Аргументы: `manage.py build_vector_index`
9. Рабочая папка: `D:\Programming\Protfolio\upx100`

Или используйте PowerShell скрипт:

```powershell
# Создайте файл update_index.ps1
cd D:\Programming\Protfolio\upx100
.\venv\Scripts\Activate.ps1
python manage.py build_vector_index
```

## Проверка работы

1. Запустите сервер:
   ```bash
   python manage.py runserver
   ```

2. Откройте `http://127.0.0.1:8000/search/`

3. Введите запрос, например: "мужская стрижка"

4. Поиск должен находить услуги даже при неточном совпадении слов!

## Возможные проблемы

### Недостаточно памяти

Ошибка: `MemoryError` или `memory allocation failed`

**Решение:**
- Увеличьте оперативную память сервера (минимум 2GB)
- Используйте более легковесную модель (например, `LaBSE` ~400MB)
- Вернитесь к TF-IDF альтернативе

### Ошибки при загрузке модели

Ошибка: `huggingface_hub` не может загрузить модель

**Решение:**
- Проверьте интернет-соединение
- Освободите место на диске (требуется ~500MB)
- Попробуйте загрузить модель вручную:
  ```python
  from sentence_transformers import SentenceTransformer
  model = SentenceTransformer('paraphrase-multilingual-MiniLM-L12-v2')
  ```

### FAISS не находит результаты

**Причины:**
- Нет активных услуг проверенных компаний
- Индекс не построен или устарел

**Решение:**
1. Убедитесь, что есть услуги со статусом `active`
2. Компании должны быть проверенными (`is_verified=True`)
3. Перестройте индекс: `python manage.py build_vector_index`

## Как это работает

1. **Векторизация текста**: Каждая услуга преобразуется в текст (название + описание + компания + категория)

2. **Генерация эмбеддинга**: Модель Sentence Transformer создаёт вектор размером 384 измерения

3. **Индексация FAISS**: Векторы нормализуются и добавляются в индекс для быстрого поиска

4. **Поиск**: 
   - Запрос пользователя векторизуется
   - FAISS находит ближайшие векторы по косинусному сходству
   - Возвращаются ID наиболее релевантных услуг

## Архитектура хранения

- **ServiceEmbedding** (ForeignKey): хранит вектор каждого сервиса
- **Специальная запись** (service_id=-1): хранит сам индекс FAISS
- **Кэш в памяти**: глобальные переменные для быстрого доступа

## Производительность

- **Построение индекса**: ~1-5 секунд для 100-1000 услуг
- **Поиск**: <10ms для любого количества услуг
- **Память**: ~10MB на 1000 услуг (эмбеддинги 384 float32)
