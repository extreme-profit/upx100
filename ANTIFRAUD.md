# Блокировки исполнителей

Исполнитель, работающий один, остаётся предпринимателем. Отсутствие сотрудников и одна жалоба не создают автоматическую блокировку.

## Решение администратора

В карточке предпринимателя в `/dashboard/users/ID/` нажмите «Подтвердить мошенничество / запретить повторную публикацию». Укажите причину, материалы проверки и подтвердите факт проверки. Дополнительные подтверждённые телефоны и публичные IP можно внести по одному в строке.

Ограничение не имеет срока окончания. Оно скрывает все услуги и запрещает создание и редактирование услуг, включая прямой POST. Оно действует отдельно от обычной блокировки за неоплату. Снятие обычной блокировки, включение аккаунта и повторная модерация не обходят антифрод-ограничение.

Реестр `/dashboard/blocks/` показывает текущие заблокированные аккаунты, решения и попытки обхода. Ошибочное решение можно пересмотреть с обязательной причиной; история не удаляется. Остальные действующие решения и обычные блокировки сохраняются. Материалы конкретного решения выгружаются в JSON только администратором. Это сохранённые сведения платформы, а не удостоверение личности или готовое заключение о преступлении.

## Повторная регистрация

Телефон при регистрации обязателен. Для российских номеров `+7 (999) ...`, `8 (999) ...` и `999...` сравниваются как один номер. Десятизначный номер считается российским; для других стран указывайте международный код. Учитываются телефон владельца, телефон компании и накопленная история контактов. Совпадение с действующим реестром сохраняет новый аккаунт и компанию с запретом публикации. Обычный ответ регистрации остаётся «ожидайте проверки», отдельного письма исполнителю нет. Всем активным администраторам платформы (`role=admin` либо суперпользователь) отправляется письмо; SMTP-ошибки сохраняются в общей очереди писем. Также попытка видна в реестре.

Существующие компании с совпавшими контактами или наблюдавшимися заблокированными IP тоже скрываются при подтверждении решения. Связанные аккаунты остаются ограниченными, даже если затем изменили телефон.

Телефон пока не подтверждается SMS. Поэтому совпадение номера — техническое правило платформы, а не надёжная идентификация человека. Другой телефон, почта и сеть могут обойти такие признаки; абсолютную невозможность повторной регистрации они не гарантируют. Следующий уровень защиты — подтверждение номера и проверка реквизитов предпринимателя.

## IP и обратный прокси

Опция блокировки по сохранённым публичным IP включена в форме решения по умолчанию; её можно отключить перед подтверждением. Один публичный IP может использоваться несколькими людьми, поэтому проверяйте материалы до включения ограничения.

Внутренние, локальные и не являющиеся публичными адреса сохраняются в истории, но не используются для автоматической блокировки. По умолчанию источником является `REMOTE_ADDR`. `X-Forwarded-For` от произвольного клиента игнорируется.

Если Django работает за доверенным nginx/балансировщиком, укажите **только реальные адреса/сети своих прокси** в окружении, например:

```dotenv
ANTIFRAUD_TRUSTED_PROXY_CIDRS=127.0.0.1/32,::1/128
```

Этот пример подходит только если nginx находится на том же сервере и доступ к Django извне закрыт. Прокси должен корректно перезаписывать или дополнять X-Forwarded-For. Не задавайте `0.0.0.0/0` или `::/0`. Алгоритм проверяет цепочку справа налево и выбирает первый недоверенный адрес.

История IP появляется только после установки функции: успешная регистрация, вход, сохранение профиля, услуги и запрещённые попытки публикации. Старые IP задним числом восстановить нельзя.

## Установка

```bash
python manage.py migrate
```

Применяются `business.0017` и `accounts.0003`. Существующие обычные блокировки автоматически в подтверждённые случаи мошенничества не переводятся. Обновлена страница политики обработки данных. Материалы и выгрузки следует передавать государственным органам при наличии законного основания.
