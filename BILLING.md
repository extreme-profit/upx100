# Публикация, заявки и ежемесячная оплата

Услуги публикуются бесплатно после проверки компании. Предоплата и старые
`payment_due_date` больше не влияют на поиск. Заблокированные компании,
отключённые аккаунты владельцев и архивные услуги не видны в публичном каталоге,
на главной странице, в поиске и по прямым ссылкам. Новые заявки на них недоступны.

При отправке заявки клиент указывает обязательный email. Владелец получает
уведомление и принимает или отклоняет заявку в ЛК. Решение допускается только
POST-запросом владельца компании или активного сотрудника, назначенного на слот. Повторный запрос не меняет решение и не создаёт
повторное письмо. Отклонение освобождает время для другого клиента.

## Начисления

- Расчётный месяц — месяц **первого подтверждения** заявки, по `Europe/Moscow`.
  Дата создания заявки и дата оказания услуги не определяют месяц начисления.
- За каждую услугу, по которой было хотя бы одно подтверждение, начисляется
  **100 ₽**, независимо от цены услуги и количества подтверждений.
- В начале следующего месяца создаётся один счёт компании с перечнем услуг.
  Без подтверждённых заявок счёт не создаётся.
- Срок оплаты — **5 число включительно**. Просрочка начинается 6 числа.
- 1 числа отправляется «Пора оплатить», 3 числа — срочное напоминание о санкциях.
  Оплаченные счета не получают напоминания. Пропущенный запуск восстанавливает
  счета и отправляет актуальное напоминание, без дублирования при повторных запусках.
- Автоматической блокировки за просрочку нет. Администратор решает её вручную.
  Архивирование услуги не удаляет уже подтверждённые заявки и начисления.
- Ранее подтверждённые заявки не имеют достоверной даты первого подтверждения.
  Миграция оставляет `confirmed_at` пустым: они не создают ретроспективных
  начислений автоматически. При необходимости их можно перенести отдельно
  после восстановления точной истории.

## Эквайринг Точка-Банка

Счета создаются локально по прежним правилам, для каждого ставится в очередь формирование платёжной ссылки через API Точки. Режим по умолчанию — настоящая песочница банка, не локальная заглушка. Сервер проверяет оплату методом Get Payment Operation Info. Браузер не может подтвердить оплату. Настройка, ограничения песочницы и получение рабочих ключей: [TOCHKA.md](TOCHKA.md).

## Почта

Локально используется консольный backend: письма видны в журнале, а не в почтовом ящике.
Для реальной отправки настройте переменные окружения:

```text
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=<SMTP-сервер>
EMAIL_PORT=587
EMAIL_HOST_USER=<учётная запись>
EMAIL_USE_TLS=True
EMAIL_USE_SSL=False
DEFAULT_FROM_EMAIL=<адрес отправителя>
SITE_URL=https://42master.ru
```

`EMAIL_HOST_PASSWORD` задавайте через защищённые настройки окружения, не в Git.
При использовании порта 465 обычно нужны `EMAIL_USE_SSL=True` и `EMAIL_USE_TLS=False`.
Недоступность SMTP не отменяет заявку или решение: письмо остаётся в
`EmailNotification` и повторяется планировщиком. Статус виден в Django admin.
Как у обычной SMTP-доставки, сбой после принятия письма сервером, но до сохранения
результата в БД, может привести к повторной доставке.

## Запуск

После обновления кода в активированном виртуальном окружении:

```bash
python manage.py migrate --noinput
python manage.py check
python manage.py test business --noinput
```

Для автоматической работы запустите **отдельный постоянный процесс** рядом с веб-сервером
и настройте его перезапуск через менеджер процессов:

```bash
python manage.py run_business_scheduler --interval 60
```

Он проверяет расчётный месяц и нужные напоминания, а также повторяет неотправленные письма.
Для однократного запуска (или использования собственного cron/Celery beat):

```bash
python manage.py process_monthly_billing
```

Достаточно одного планировщика. Django `runserver` самостоятельно задачи не запускает.
В подготовленной облачной среде рабочая директория — `/workspace/upx100`, перед командами
выполните `source /workspace/upx100-local/activate.sh`: это использует отдельную SQLite-базу
разработки и сохраняет исходную базу репозитория.

## Ручная блокировка

В `/dashboard/users/<id>/` у компании есть кнопка **«Заблокировать все услуги»**.
Она скрывает текущие и будущие услуги, сохраняя доступ владельца к ЛК и оплате.
Разблокировка возвращает неархивные услуги проверенной компании в каталог.
То же доступно через поле `is_blocked` и групповые действия компаний/пользователей
в Django admin. Отключение аккаунта (`is_active=False`) отдельно запрещает вход
и также скрывает услуги.

## Регистрация и отмена клиентом

Клиент получает письмо о регистрации сразу после создания заявки и отдельное письмо с решением. В письмах о регистрации и подтверждении есть индивидуальная подписанная ссылка отмены. GET открывает страницу, отмена выполняется только POST с CSRF. Можно отменить ожидающую или подтверждённую заявку; слот освобождается, обе стороны получают письмо. Повторная отмена не создаёт новых писем. Дата первого подтверждения сохраняется для начисления платы за услугу. Ссылку следует считать конфиденциальной: её обладатель может отменить эту запись.

## Часовой пояс компании и дашборд

Часовой пояс задаётся в профиле компании (IANA, например Asia/Vladivostok). Для старых компаний устанавливается Europe/Moscow. Даты и часы слотов — местное время компании; смена пояса сохраняет их как показанные на часах, а не переносит абсолютный момент. При проверке доступности используется пояс компании. Несуществующее или неоднозначное время перехода на летнее/зимнее время недоступно для новой записи. Периоды счетов и сроки оплаты по-прежнему определяются по Europe/Moscow.

Статистика админки считается за всё время. Активный предприниматель: включённый аккаунт с проверенной и незаблокированной компанией. Список неоплативших показывает все ожидающие оплаты счета, отдельно считает просроченные (после 5 числа). Оплаченные счета не входят в задолженность.

## История клиента, форматы услуг и отчёт

История /client/bookings/ доступна по случайному UUID в подписанной HttpOnly cookie booking_visitor (SameSite=Lax, год; Secure на HTTPS). В историю попадают только новые заявки, созданные в этом браузере. Удаление cookie или другой браузер создаёт новую историю; перенос старых заявок по email не выполняется. Момент записи сохраняется отдельно от слота, поэтому остаётся в истории после отмены. Текущие — pending/confirmed с будущим временем; прошедшие включают завершённые и отменённые.

Адрес компании включён в письмо с решением, страницу результата и историю. Формат оказания услуги задаётся отдельно от категории: remote (удалённо), onsite (на месте, значение для старых услуг), visit (выезд). Категория и формат совместно фильтруются в поиске. Адрес компании не является адресом выезда клиента.

Город заполняется отдельно в профиле компании. Для старых компаний остаётся пустым и доступен фильтр «Город не указан». Отчёт /dashboard/payments/ доступен только администратору, фильтруется по городу и оплате; CSV выгружает все подходящие строки, независимо от пагинации. «Оплатили» — есть оплаченные счета и нет неоплаченных; «Не оплатили» — есть неоплаченные; «Без счетов» — счетов не было. Суммы за всё время, CSV UTF-8 с BOM и разделителем «;». Значения, похожие на формулы, экранируются.

## Рейтинг мастеров и отзывы

Для новых записей сохраняются мастер и точное время окончания слота в поясе компании, в том числе при переходе через полночь. После окончания подтверждённой или выполненной записи клиент может оставить один отзыв (1–5, текст до 2000 символов) по индивидуальной случайной UUID-ссылке. Та же ссылка доступна в истории этого браузера. Отменённые и неподтверждённые заявки, будущие услуги и записи без назначенного мастера не допускают отзыв. Повторная отправка не изменяет первоначальный отзыв.

Через 24 часа после планового окончания услуги process_monthly_billing создаёт письмо с приглашением. Это выполняется существующим run_business_scheduler; требуются работающий планировщик и SMTP. Письмо не отправляется, если отзыв уже оставлен. Система определяет окончание по расписанию подтверждённой записи, а не получает подтверждение фактического оказания услуги от внешней системы. Старые записи без сохранённого мастера и времени окончания автоматически не получают приглашений.

На странице услуги средняя оценка и количество отзывов показаны для каждого активного мастера; мастера упорядочены по оценке и числу отзывов. Ниже — 20 последних отзывов этих мастеров. Текст публичен и экранируется; имя, email и телефон клиента не публикуются. Администратор может просматривать и удалять отзывы через Django admin.


## Неявки и причины отказа

Исполнитель отмечает «Клиент не пришёл» только у подтверждённой записи после планового окончания. Предприниматель может отметить свои записи, активный сотрудник — только назначенные ему. Повторный POST не создаёт вторую неявку. В админке /dashboard/no-shows/ появляется сообщение с данными клиента, предпринимателя и автора отметки. Администратор может отметить проверку или отменить ошибку с обязательной причиной; отметка и история её рассмотрения остаются в БД.

Три действующие отметки за календарный месяц (по дате начала записи, Europe/Moscow) дают предупреждение клиенту и исполнителю при следующих заявках. Статус пересчитывается при смене месяца и после отмены ошибочной отметки. Запись не запрещается автоматически. Для сопоставления используются UUID браузера, нормализованный email или телефон, без транзитивного объединения контактов. IP сохраняется из REMOTE_ADDR, не из недоверенных X-Forwarded-For. За reverse proxy реальный адрес должен корректно передаваться в REMOTE_ADDR доверенной инфраструктурой. IP не используется как самостоятельное доказательство идентичности или ненадёжности.

Неявки исключены из учитываемых подтверждённых записей, рейтинга мастера и новых начислений. Если других учитываемых записей по услуге за расчётный месяц нет, строка удаляется из неоплаченного счёта; нулевой счёт аннулируется. После отмены ошибочной неявки строка и неоплаченный счёт восстанавливаются. Об изменении суммы отправляется письмо, неотправленные напоминания со старой суммой подавляются. Уже оплаченный счёт автоматически не меняется: в админке появляется отметка о необходимости ручной корректировки/возврата. Эквайринг работает в песочнице Точки; переход в live описан в TOCHKA.md. Неподтверждённые приглашения к отзыву для неявок не отправляются; уже опубликованный отзыв скрывается из публичного рейтинга до отмены неявки.

IP, исходные email и телефон и их нормализованные значения хранятся в Booking. В политике описаны цели обработки, доступ исполнителя/администратора и обращение в http://6max.ru/admin_extreme_profit для оспаривания, исправления или удаления. Отметки считаются сообщениями исполнителей, а не безусловно доказанным нарушением; администратор может проверять их звонком.

Для отказа в pending-заявке обязательна причина до 1000 символов. Она сохраняется, попадает в письмо с решением и показывается клиенту в истории/результате заявки. Старые отказы остаются без восстановленной задним числом причины.


Адрес поддержки во всех публичных страницах, предупреждениях, письмах и меню панелей: http://6max.ru/admin_extreme_profit.


## Колокольчик комиссии в ЛК

Владелец компании видит колокольчик с количеством непрочитанных уведомлений и пятью последними событиями. В /business/notifications/ — вся история с пагинацией, отметкой прочитанного и переходом к счёту. Финансовые уведомления доступны только предпринимателю-владельцу; сотрудники не получают доступа к чужим или корпоративным счетам через колокольчик. Отметки прочтения меняются только POST с CSRF.

При формировании счёта или первом запуске планировщика для существующего неоплаченного счёта создаётся уведомление «Пора оплачивать комиссию за услуги». 3 числа появляется срочное напоминание, после 5 — уведомление о просрочке. Отдельные события создаются при подтверждении оплаты банком, корректировке, аннулировании и необходимости ручной корректировки оплаченного счёта. Повторные запуски не создают дубликаты и не сбрасывают прочтение. Рассылка по почте продолжает работать независимо от колокольчика.

Каждое уведомление сохраняет расшифровку на момент события: услуги из счёта, сотрудники и количество учтённых подтверждений за расчётный месяц (по confirmed_at), без неявок. Для старых записей без снимка мастера используется сотрудник сохранённого слота; если назначение неизвестно, показывается «Сотрудник не указан». Количество броней не умножает плату: две учтённые услуги — 2 × 100 = 200 ₽. Поздняя отмена клиентом подтверждённой записи по-прежнему учитывается согласно исходному правилу начисления за подтверждение; неявки исключены. В истории виден и текущий статус связанного счёта, а актуальная сумма — по ссылке на него.

Требуется миграция 0013. Новые уведомления формируются существующим process_monthly_billing / run_business_scheduler; в ЛК видны при загрузке страницы, без отдельного сервиса push-уведомлений.


Бренд интерфейса и писем — 42master.ru. Логотип берётся из static/img/logo.png; файл добавляется владельцем отдельно. Внешние ссылки и отправитель по умолчанию используют 42master.ru; переменные SITE_URL и DEFAULT_FROM_EMAIL на сервере имеют приоритет над значениями по умолчанию. В отчёте по оплатам и CSV выводится город компании; фильтр по городу сохраняется.
