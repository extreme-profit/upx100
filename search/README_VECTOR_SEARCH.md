# Настройка векторного поиска для Django проекта

## Обзор

Векторный поиск позволяет выполнять семантический поиск услуг, а не только побуквенное совпадение.
Это значит, что поиск будет находить услуги по смыслу, даже если запрос не точно совпадает с названием.

## Используемая технология

Используется TF-IDF векторизация + косинусное сходство - легковесная альтернатива FAISS, 
которая работает при ограниченных ресурсах (память, диск).


### Ручное построение

```bash
python manage.py build_vector_index
```

### Автоматическое обновление (каждый день в 3:00)

Добавьте в crontab:

```bash
crontab -e
```

Добавьте строку:

```

```

Или используйте готовый скрипт:

```bash
# Отредактируйте путь к проекту если нужно
echo "0 3 * * * /workspace/search/build_index_cron.sh" | crontab -
```

## Как это работает

1. **Векторизация**: Каждая услуга преобразуется в текстовое представление, включающее:
   - Название услуги
   - Описание
   - Название компании
   - Категорию и подкатегорию

2. **TF-IDF**: Текст преобразуется в числовой вектор с помощью TF-IDF векторизатора

3. **Поиск**: При поиске запрос пользователя также векторизуется, и находятся наиболее 
   близкие векторы услуг по косинусному сходству

4. **Кэширование**: Индекс кэшируется в памяти после первой загрузки для быстрого поиска

5. **Сохранение**: Векторизатор и матрица сохраняются в базу данных в модели `ServiceEmbedding`

## Поиск в коде

В `search/views.py` используется функция `search_similar()` из `search/vector_search.py`:

```python
from .vector_search import search_similar

# Получить топ-20 наиболее релевантных услуг
similar_service_ids = search_similar(query, top_k=20)
```

## Обновление индекса

Индекс нужно перестраивать при:
- Добавлении новых услуг
- Изменении названий/описаний услуг
- Изменении статуса услуги или компании

Автоматическое обновление настроено на 3:00 ночи ежедневно.

## Примечания

- Индекс строится только для активных услуг (`status='active'`) проверенных компаний (`is_verified=True`)
- При отсутствии индекса поиск автоматически переключается на традиционный SQL LIKE поиск
- Для больших баз данных (>10000 услуг) рекомендуется рассмотреть FAISS или другие специализированные решения
